## 1. ภาพรวมเมนู 7 กลุ่ม

แถบข้างจัดเป็น 7 กลุ่มตาม flow งานจริง (ซ้ายไปขวา = ต้นน้ำไปปลายน้ำ):

| # | กลุ่ม | เมนูในกลุ่ม | สำหรับใคร |
|---|------|--------------|-----------|
| 1 | **ทำงานวันนี้** | หน้าหลัก, งานของฉัน, แชท, แจ้งเตือน, งานภายใน | ทุก role |
| 2 | **ขาย → การเงิน** | ลูกค้าเป้าหมาย, ขาย / ใบเสนอราคา, การเงิน | Sales / Admin (Finance) |
| 3 | **ส่งมอบงาน** | รับบรีฟ, โปรเจกต์, งานยิงแอด, คอนเทนต์, ครีเอเตอร์, ลูกค้า 360 | Account / Ads / Content |
| 4 | **ดูแลต่อเนื่อง** | ต่อสัญญา, พื้นที่ลูกค้า | Account / Sales |
| 5 | **รายงาน / วิเคราะห์** | ภาพรวมผู้บริหาร, สรุปรายสัปดาห์, รายงาน, บันทึกกิจกรรม | CEO / Ops |
| 6 | **เครื่องมือ / Admin** | ผู้ช่วย AI, จัดการผู้ใช้, ศูนย์ Ops | Admin / Dev |
| 7 | **ระบบ** | ตั้งค่า, ช่วยเหลือ, สถานะ | ทุก role |

> หากไม่เห็นเมนูในกลุ่มไหน = บทบาทของท่านไม่ครอบคลุม — ติดต่อผู้ดูแลระบบ

## 2. รูทีนวันทำงาน (ทุก role)

### เปิดวัน (5 นาที)

1. ล็อกอินเข้า `/app` → ดู **KPI การ์ด** (งานเกินกำหนด / งานวันนี้ / แจ้งเตือน)
2. กด **งานของฉัน** ในแถบข้าง → ปัดดู section ตามลำดับ:
   - งานเลยกำหนด
   - งานวันนี้
   - คำขอที่ต้อง action
3. กด **แจ้งเตือน** (ไอคอนกระดิ่ง) → อ่านและ archive ข้อความที่ไม่ต้อง action

### ระหว่างวัน (ตามจังหวะ)

| สิ่งที่เกิด | ไปที่ | ทำอะไร |
|-------------|--------|--------|
| ลูกค้าทักมา LINE | **แชท** | ตอบ / ส่งให้คนรับผิดชอบ |
| มีงานใหม่จากผู้จัดการ | **งานภายใน** | รับงาน → ปรับสถานะ doing |
| สลิปลูกค้าเข้ามา | **การเงิน** (Admin) | ตรวจ OCR → ยืนยัน / ปฏิเสธ |

### ปิดวัน (5 นาที)

1. กลับเข้า **งานของฉัน** → ปิด task ที่เสร็จแล้ว
2. ตั้ง due date ของงานพรุ่งนี้ใน **งานภายใน**
3. (ผู้จัดการขึ้นไป) ดู **ภาพรวมผู้บริหาร** → ตรวจตัวเลขประจำวัน

## 3. Flow A — ขาย (Sales → Finance)

```
ลูกค้าทัก  →  Lead  →  Quotation  →  ลูกค้ายืนยัน  →  สลิป  →  ใบเสร็จ
   ↑          ↑          ↑              ↑              ↑          ↑
  LINE      CRM        ขาย          public /q       Finance    Finance
```

### A1. รับ Lead ใหม่ (Sales)

1. ไป **ลูกค้าเป้าหมาย** (`/app/crm`)
2. กด **+ Lead ใหม่** หรือลาก Lead จาก LINE/แชท
3. กรอก: ชื่อลูกค้า, ช่องทาง, แพ็กเกจสนใจ, งบประมาณ
4. กำหนด **ผู้รับผิดชอบ** (claim ให้ตัวเอง หรือมอบหมาย)
5. ตั้งสถานะเริ่มต้น = `new` หรือ `qualified`
6. (ถ้ามี) แนบไฟล์/รูปจากการคุย → tab **ไฟล์แนบ**

### A2. สร้าง Quotation (Sales)

1. ใน Lead → กด **สร้างใบเสนอราคา** หรือไป **ขาย / ใบเสนอราคา** (`/app/sales`)
2. เลือก Lead/ลูกค้า → เลือกแพ็กเกจ (มาจาก Master packages)
3. ปรับ **รายการ** (description, qty, price, discount)
4. ตั้ง **เงื่อนไขการชำระ**: เต็มจำนวน / มัดจำ + งวด
5. กด **บันทึก** → สถานะ `draft`
6. ตรวจ preview → กด **เผยแพร่** (publish) → สถานะ `sent`
7. กด **ส่งลิงก์ลูกค้าทาง LINE** → ระบบสร้าง public link `/q/<token>` และส่งผ่าน LINE OA

### A3. ลูกค้ายืนยันและอัปโหลดสลิป (ฝั่งลูกค้า)

ลูกค้าจะเห็นหน้า `/q/<token>` ผ่าน LINE — ขั้นตอนของลูกค้า (เพื่อให้ทีมรู้ว่ามาถึงไหน):

1. กด **ยืนยันใบเสนอราคา** → สถานะ Quotation = `accepted`
2. หน้าเปลี่ยนเป็น **ข้อมูลการชำระเงิน** + QR Promptpay
3. ลูกค้าจ่ายเงิน → กลับมาในหน้าเดิม → **อัปโหลดสลิป**
4. ระบบจะ:
   - อัปโหลด slip ไป Supabase Storage
   - เรียก Edge Function `verify-payment-slip` (OCR)
   - ส่ง LINE แจ้ง “ได้รับสลิปแล้ว” + “กำลังตรวจสอบ”
5. หน้าจอลูกค้าแสดง **Progress stepper**: รอตรวจสอบ → ผ่าน → ออกใบเสร็จ

## 4. Flow B — รับเงิน (Finance)

> ผู้รับผิดชอบหลัก = `admin` (Finance), เสริม = `operations`, `ceo`

### B1. ตรวจสลิปที่ระบบ flag ไว้ (Daily)

1. ไป **การเงิน** (`/app/finance`) → tab **คิวรอตรวจสอบ**
   หรือดูจาก **หน้าหลัก** section *“สลิปรอรีวิว”*
2. คลิกรายการ → หน้า **PaymentEditor** เปิดขึ้น:
   - รูปสลิป (zoomable)
   - ผล OCR (จำนวนเงิน / วัน / เวลา / ธนาคารต้นทาง)
   - Confidence (สีเหลือง/แดง ถ้าต่ำ)
3. ตรวจสาม **field critical**:
   - `amount` ตรงใบเสนอราคา?
   - `paid_at` วันที่เหมาะสม?
   - บัญชีปลายทางตรงบัญชีบริษัทหรือไม่?

### B2. ผลลัพธ์เป็นไปได้ 3 ทาง

| สถานการณ์ | ปุ่มที่กด | ผลที่เกิด |
|-----------|----------|----------|
| ตรงทุก field, confidence สูง | **ยืนยันการชำระ** | สถานะ → `paid`, ออกใบเสร็จอัตโนมัติ, ส่ง LINE confirm |
| ข้อมูลถูกแต่ confidence ต่ำ | **ยืนยันการชำระ** (override) | บันทึก log ว่า manual override |
| สลิปปลอม / ผิดบัญชี / amount ผิด | **ปฏิเสธสลิป** → กรอกเหตุผล | สถานะ → `review_required`, ลูกค้าได้ LINE + เห็น banner บนหน้า `/q/<token>` |

### B3. รัน Bank Statement Matching (สัปดาห์ละครั้งขึ้นไป)

1. ไป **การเงิน** → tab **กระทบยอดธนาคาร**
2. กด **อัปโหลด CSV ธนาคาร** → preview modal แสดงรายการ
3. ตรวจคอลัมน์ที่ระบบจับคู่ → กด **ยืนยันนำเข้า**
4. ระบบจะรัน `find_bank_match_for_line` กับทุก payment ที่ยัง `pending/verifying`
5. รายการที่จับคู่ได้จะ **highlight สีเขียว** → กด **ยืนยัน** ทีละรายการ
   (หรือใช้ **ยืนยันทั้งหมดที่ตรง 100%**)
6. รายการที่ไม่ match → ตรวจ manual หรือ ignore

### B4. ออกใบเสร็จ / Tax Invoice (อัตโนมัติ + manual)

- **อัตโนมัติ**: เมื่อ status = `paid` ระบบสร้าง receipt + เลขที่ตามรูปแบบบริษัท
- **Manual**: ใน PaymentEditor → กด **ออกใบเสร็จเพิ่มเติม** (กรณีลูกค้าขอชื่อ/ที่อยู่ใหม่)
- พิมพ์/ดาวน์โหลด PDF → tab **เอกสาร**

## 5. Flow C — ส่งมอบงาน (Delivery)

> หลัง payment status = `paid` → flow Delivery เริ่มทำงาน

### C1. รับบรีฟลูกค้า (Account)

1. ไป **รับบรีฟลูกค้า** (`/app/onboarding`)
2. ระบบจะแสดง Quotation ที่ paid แต่ยังไม่เริ่ม onboarding
3. เปิดรายการ → กรอก **Brand Brief**:
   - ชื่อแบรนด์, BU, สินค้า, target audience
   - Tone, ข้อห้าม
   - Link material (Drive / Notion)
4. กด **เริ่มโปรเจกต์** → ระบบสร้าง Project + แจ้งทีม

### C2. จัดการ Project (Account / Operations)

1. ไป **โปรเจกต์** (`/app/projects`) → เลือกโปรเจกต์ใหม่
2. ตั้ง **Milestones** ตามแพ็กเกจ (เช่น: เซ็ตอัป → คอนเทนต์เดือนที่ 1 → คอนเทนต์เดือนที่ 2)
3. แบ่งงานเป็น **subtasks** → assign ทีม Ads / Content / Creators
4. ปรับสถานะ project = `in_progress`

### C3. ยิงแอด (Ads / Senior Ads)

1. ไป **งานยิงแอด** (`/app/ads`) → เห็นแคมเปญที่ assign ให้
2. กด **เริ่มแคมเปญ** → เปลี่ยนสถานะ → กรอก campaign id จาก Meta/TikTok
3. รายงานผลรายวัน/สัปดาห์ → tab **Performance** (impressions, clicks, spend, leads)
4. ปิดแคมเปญ → สถานะ `completed`

### C4. คอนเทนต์ (Content)

1. ไป **งานคอนเทนต์** (`/app/content`) → คิวงานตามวันส่งมอบ
2. เลือกงาน → กด **เริ่มทำ** → tab **เนื้อหา**:
   - ลิงก์ draft (Drive/Figma)
   - script / caption
   - ครีเอเตอร์ที่ใช้ (เลือกจาก **ครีเอเตอร์** `/app/creators`)
3. ส่งให้รีวิว → สถานะ `review`
4. ส่งลูกค้า approve → สถานะ `approved`
5. โพสต์/ส่งมอบ → สถานะ `delivered`

### C5. ลูกค้า 360 (CEO / Ops / Account)

1. ไป **ลูกค้า 360** (`/app/customers`)
2. ค้นชื่อลูกค้า → หน้ารวมข้อมูล:
   - Lead ต้นทาง
   - Quotation / Payment / สัญญา
   - งานแอด / คอนเทนต์ที่กำลังทำ
   - Timeline กิจกรรม
3. ใช้สำหรับ **brief meeting** หรือ **handover** ระหว่างทีม

## 6. Flow D — ดูแลต่อเนื่อง (Retention)

### D1. ต่อสัญญา (Sales / Account)

1. ไป **ต่อสัญญา** (`/app/renewals`)
2. ระบบแสดงสัญญาเรียงตาม **วันหมดอายุที่ใกล้ที่สุด**
3. รายการ flag สี:
   - 🔴 หมดแล้ว / เลย 7 วัน
   - 🟡 เหลือ < 30 วัน
   - 🟢 ยังไกล
4. คลิกรายการ → ดู history → กด **เริ่ม Quotation ต่อ** → กลับเข้า Flow A

### D2. พื้นที่ลูกค้า (Client / Account)

- **ฝั่งลูกค้า** (login เป็น `client`): เห็น report งานเดือนนี้, ใบเสร็จ, ตารางคอนเทนต์
- **ฝั่งทีม**: ใช้ดูว่าลูกค้าเห็นอะไร — ทดสอบก่อนเปิดให้ลูกค้าใช้

## 7. Flow E — รายงาน / วิเคราะห์ (Analytics)

### E1. รายวัน (Ops / CEO)

- **ภาพรวมผู้บริหาร** (`/app/dashboard`) → KPI สด:
  - รายได้เดือน vs target
  - Lead ใหม่ / ปิดดีล
  - งานเลยกำหนด

### E2. รายสัปดาห์ (Ops / Account / CEO)

1. **สรุปรายสัปดาห์** (`/app/weekly`) → เลือกสัปดาห์
2. ระบบสรุป:
   - งานทำเสร็จ vs ค้าง
   - การเงินไหลเข้า
   - คอนเทนต์/แอดที่ส่งมอบ
3. **export** → แชร์ในประชุมประจำสัปดาห์

### E3. รายเดือน / เฉพาะกิจ (CEO / Admin)

- **รายงานขั้นสูง** (`/app/reports`) → custom report (รายได้ตามแพ็กเกจ, ลูกค้า top, ฯลฯ)
- **บันทึกกิจกรรม** (`/app/activity`) → audit log (ใครทำอะไร เมื่อไร)

## 9. ลำดับงานตามบทบาท (Cheat-sheet)

### Sales

```
หน้าหลัก  →  งานของฉัน (Lead ค้าง)  →  CRM (รับ Lead)  →  ขาย (Quotation)
   ↓
ส่ง LINE ลิงก์  →  รอลูกค้าจ่าย  →  Finance ยืนยัน  →  ต่อสัญญา (อีก 30 วัน)
```

### Account

```
หน้าหลัก  →  รับบรีฟ (paid quotes)  →  โปรเจกต์ (สร้าง milestone)
   ↓
แชท (คุยลูกค้า)  →  ลูกค้า 360 (รวมข้อมูล)  →  ต่อสัญญา
```

### Ads / Senior Ads

```
หน้าหลัก  →  งานยิงแอด (คิว)  →  เลือกแคมเปญ  →  รายงานผลรายวัน
   ↓
ปิดแคมเปญ  →  แจ้ง Account รีพอร์ตลูกค้า
```

### Content / Creative

```
หน้าหลัก  →  งานคอนเทนต์ (คิว)  →  ครีเอเตอร์ (เลือกคน)  →  ส่ง draft
   ↓
รีวิว  →  ส่งลูกค้า approve  →  ส่งมอบ
```

### Admin (Finance)

```
หน้าหลัก  →  การเงิน (สลิปคิว)  →  ตรวจ OCR  →  ยืนยัน/ปฏิเสธ
   ↓
นำเข้า CSV ธนาคาร  →  จับคู่  →  ออกใบเสร็จ
```

### Operations / CEO

```
หน้าหลัก (KPI)  →  ภาพรวมผู้บริหาร  →  สรุปสัปดาห์  →  รายงานขั้นสูง
   ↓
ลูกค้า 360 (เคสที่ต้องช่วย)  →  ศูนย์ Ops (ตรวจ system)  →  จัดการผู้ใช้
```

## 10. เคสพิเศษ / Troubleshooting

### กรณี OCR ตรวจไม่ออก / Confidence ต่ำ

1. เข้า PaymentEditor → ดูรูปสลิป
2. กรอก field manual (amount, paid_at, sender_bank)
3. กด **บันทึก & ยืนยัน** → ระบบจะ log ว่า manual

### กรณีลูกค้าอัปโหลดสลิปผิด

1. Admin กด **ปฏิเสธสลิป** + เหตุผล (ภาษาไทย ลูกค้าเห็นเลย)
2. ลูกค้าจะได้ LINE message + banner บนหน้า `/q/<token>`
3. ลูกค้าอัปโหลดสลิปใหม่ได้เลย → กลับเข้า Flow B

### กรณีลูกค้าโอนเข้าผิดบัญชี

1. Admin **ปฏิเสธสลิป** + ระบุ “โอนเข้าผิดบัญชี กรุณาโอนใหม่ไป …”
2. หลังโอนใหม่ → ลูกค้าอัปโหลดสลิปใหม่
3. CSV bank statement อัปโหลดเข้ามาแล้วจะจับคู่ได้เอง

### กรณีพนักงานลืมรหัสผ่าน

1. แจ้งผู้ดูแล (CEO / Operations)
2. ผู้ดูแลไป **จัดการผู้ใช้** → เลือกบัญชี → **รีเซ็ตรหัสผ่าน**
3. แจ้งรหัสใหม่ผ่านช่องทางส่วนตัว → ให้พนักงานเปลี่ยนเมื่อเข้าครั้งแรก

### กรณีล็อกอินไม่เห็นเมนูที่ควรเห็น

1. เช็ก **ตั้งค่า** → ดู badge บทบาทตรงไหม
2. ถ้าไม่ตรง → แจ้งผู้ดูแลให้แก้ใน **จัดการผู้ใช้**
3. logout/login อีกครั้ง

### กรณี LINE ไม่ส่งไป

1. เปิด **สถานะ** (`/app/status`) → ดูแถว LINE Connector
2. ถ้าแดง → แจ้ง Ops/Dev เช็ก secret/access token ใน `settings`
3. หลังแก้ → กด **ส่งซ้ำ** ใน PaymentEditor / Quotation page
